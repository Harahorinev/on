# Настройка отправки email (сброс пароля и уведомления)

Чтобы письма сброса пароля реально отправлялись, на сервере нужно задать переменные окружения для бэкенда.

## 1. FRONTEND_URL

Ссылка в письме ведёт на страницу сброса пароля фронта. Бэкенд подставляет сюда свой базовый URL.

**Что задать:** полный URL фронта без завершающего слэша.

| Среда        | Пример                    |
|-------------|---------------------------|
| Продакшен   | `https://och-net.ru`      |
| Локально    | `http://localhost:5173`   |

Если `FRONTEND_URL` не задан, письмо с ссылкой **не отправляется** (токен создаётся, но пользователь не получит ссылку).

---

## 2. SMTP (отправка писем)

Бэкенд отправляет письма через SMTP. Нужны: хост, порт, логин и пароль.

### Обязательные переменные

| Переменная   | Описание                    | Пример (Yandex)      |
|-------------|-----------------------------|----------------------|
| `SMTP_HOST` | Сервер SMTP                 | `smtp.yandex.ru`     |
| `SMTP_PORT` | Порт (обычно 465 для SSL)   | `465`                |
| `SMTP_USER` | Логин SMTP                  | твой@yandex.ru       |
| `SMTP_PASS` | Пароль от почты (или пароль приложения, если включён) | секрет |

### Опциональные

| Переменная      | Описание                                      |
|-----------------|-----------------------------------------------|
| `SMTP_SECURE`   | `true` для порта 465 (SSL), иначе `false`     |
| `MAIL_FROM`     | Адрес отправителя (по умолчанию = SMTP_USER) |
| `MAIL_FROM_NAME`| Имя отправителя в письме (по умолчанию "On") |

Если хотя бы один из `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` не задан, бэкенд **не отправляет** письма (логирует и продолжает работу).

---

## 3. Где взять SMTP (рекомендуется: Yandex)

### Yandex — основной вариант

1. Зайди в [Почту Яндекса](https://mail.yandex.ru) и в **Настройки → Почтовые программы** включи:
   - **С сервера imap.yandex.ru по протоколу IMAP**
   - при необходимости — доступ по SMTP для приложений (если Яндекс попросит «пароль приложения», создай его в [Пароли и авторизация](https://id.yandex.ru/security/app-passwords)).
2. В `.env` на сервере задай:

| Переменная    | Значение для Yandex      |
|---------------|---------------------------|
| `SMTP_HOST`   | `smtp.yandex.ru`          |
| `SMTP_PORT`   | `465`                     |
| `SMTP_SECURE` | `true`                    |
| `SMTP_USER`   | твой полный адрес @yandex.ru |
| `SMTP_PASS`   | пароль от почты или пароль приложения |

В `SMTP_PASS` указывается тот пароль, который принимает Yandex при SMTP-подключении: как правило это **обычный пароль от ящика**. Если в аккаунте включён вход по «паролю приложения» для почтовых программ — в `SMTP_PASS` нужно подставить именно **пароль приложения**, а не основной пароль.

### Gmail

Пароли приложений есть не у всех: нужна двухфакторная аутентификация, и для части аккаунтов (Workspace, корпоративные) настройка может быть отключена — тогда появится сообщение «Эта настройка недоступна для вашего аккаунта». В таком случае используй другой SMTP (Yandex, Mail.ru, Mailgun и т.д.).

Если пароли приложений доступны:

1. Включи двухфакторную аутентификацию: [Google Account → Security](https://myaccount.google.com/security).
2. Создай «Пароль приложения»: [App passwords](https://myaccount.google.com/apppasswords).
3. Настрой:
   - `SMTP_HOST=smtp.gmail.com`
   - `SMTP_PORT=587`
   - `SMTP_SECURE=false`
   - `SMTP_USER=твой@gmail.com`
   - `SMTP_PASS=пароль_приложения_16_символов`

### Mail.ru

- `SMTP_HOST=smtp.mail.ru`
- `SMTP_PORT=465`, `SMTP_SECURE=true` (или порт 587 без SSL — см. справку Mail.ru)
- `SMTP_USER` и `SMTP_PASS` — логин и пароль от @mail.ru. В настройках почты может потребоваться включить доступ для внешних приложений.

### Mailgun / SendGrid / другой сервис

В панели сервиса найди раздел SMTP: там будут хост, порт, пользователь и пароль. Подставь их в переменные выше.

## 4. Где задать переменные на сервере

Переменные должны быть в окружении процесса, в котором запущен бэкенд (PM2, systemd и т.д.). **Не** в GitHub Secrets — секреты CI не подставляются в окружение на сервере при деплое.

### Вариант A: файл `.env` в каталоге бэкенда

В `/var/www/on/backend/` создай или отредактируй `.env` (пример для Yandex):

```bash
FRONTEND_URL=https://och-net.ru
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=твой@yandex.ru
SMTP_PASS=пароль_от_почты_или_пароль_приложения
MAIL_FROM_NAME=Онлайн-запись
```

Бэкенд уже подхватывает `.env` через `dotenv` при старте. Убедись, что `.env` не попал в git (он в `.gitignore`).

После изменения перезапусти бэкенд:

```bash
pm2 restart on-backend
```

### Вариант B: переменные в PM2

Если не используешь `.env`, задай переменные при запуске:

```bash
cd /var/www/on/backend
FRONTEND_URL=https://och-net.ru SMTP_HOST=smtp.yandex.ru SMTP_PORT=465 SMTP_SECURE=true SMTP_USER=... SMTP_PASS=... pm2 start dist/index.js --name on-backend
```

Или в ecosystem-файле PM2 задай `env` с этими переменными.

### Вариант C: systemd

В `Environment=` в unit-файле сервиса добавь нужные переменные (или укажи `EnvironmentFile=` на файл с секретами).

## 5. Какие письма отправляются (B84)

Email-уведомления отправляются только если в настройках пользователя включён переключатель **«Уведомления по email»** (`notifyEmail=true`).

На текущем этапе приходят такие письма:

1. **Запись подтверждена** — после успешного создания записи.
2. **Запись отменена** — после отмены записи пользователем.
3. **Напоминание о записи (~24 часа)** — планировщик периодически проверяет ближайшие записи и отправляет одно письмо-напоминание.

Дополнительная настройка планировщика:

| Переменная | Описание | Значение по умолчанию |
|------------|----------|------------------------|
| `BOOKING_REMINDER_INTERVAL_MS` | Интервал проверки напоминаний в миллисекундах | `900000` (15 минут) |
| `BOOKING_REMINDER_OFFSETS_MINUTES` | Смещения напоминаний в минутах через запятую | `1440` (за 24 часа) |

---

## 6. Проверка

1. Задай `FRONTEND_URL` и SMTP на сервере и перезапусти бэкенд.
2. На фронте открой «Забыли пароль?», введи email зарегистрированного пользователя и отправь форму.
3. Проверь почту (и папку «Спам»). Должно прийти письмо со ссылкой вида `https://och-net.ru/reset-password?token=...`.
4. В логах бэкенда при успешной отправке будет запись уровня info с темой письма и получателем.

Если письмо не пришло:

- Убедись, что в логах нет ошибки от nodemailer (проверь `SMTP_*`, пароль приложения, не блокирует ли хостинг исходящий SMTP).
- Убедись, что `FRONTEND_URL` задан (иначе письмо не отправляется).
